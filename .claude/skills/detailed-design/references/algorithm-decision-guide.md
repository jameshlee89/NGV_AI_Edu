# 알고리즘 · 정책 의사결정표 작성 가이드

SKILL.md §5(핵심 알고리즘/정책 의사결정표)에서 사용한다. 템플릿 6장(핵심 알고리즘), 7장(정책
의사결정표)에 대응한다.

## 1. 핵심 알고리즘 (템플릿 6장)

- 처리 순서, 판단 조건, 경계값(최소/최대/0/음수 등), 계산 근거(공식, 참조 표준)를 의사코드 또는
  흐름도로 표현한다.
- 경계값 처리는 반드시 명시한다 — "정상 범위만" 서술하고 경계/예외 입력을 누락하지 않는다.
- 알고리즘이 특정 라이브러리/하드웨어 기능의 존재를 전제로 한다면, 실제로 그 기능이 프로젝트 환경에
  존재/사용 가능한지 확인한 뒤 서술한다. 확인할 수 없으면 "실행 가능 여부 확인 필요"로 표시한다.
- 알고리즘은 §4(핵심 함수 계약)의 사전/사후조건과 일치해야 한다.

### 의사코드 작성 예시

```
FUNCTION 계산(입력 x):
    IF x < 최소값 OR x > 최대값 THEN
        RETURN 오류(범위초과)
    END IF
    결과 = ... (계산 로직)
    RETURN 결과
END FUNCTION
```

## 2. 정책 의사결정표 (템플릿 7장)

여러 입력 조건의 조합에 따라 동작이 달라지는 정책은 표로 정의한다.

| 조건1 | 조건2 | ... | 우선순위 | 기대 동작 | 비고(충돌 해결 규칙) |
|---|---|---|---|---|---|
| ... | ... | ... | ... | ... | ... |

### 점검 규칙

- **완전성(Completeness)**: 가능한 모든 조건 조합이 표에 포함되는가? 누락된 조합이 있으면 "정의되지
  않은 조합"으로 명시하고, 실제로 발생 가능한지 확인한다(발생 가능하면 반드시 채운다).
- **일관성(Consistency)**: 동일한 조건 조합에 대해 서로 다른 두 행이 다른 결과를 정의하고 있지 않은가?
- **우선순위/충돌 해결**: 여러 규칙이 동시에 적용 가능한 경우 어떤 규칙이 우선하는지 명시적으로
  정의한다("먼저 정의된 것이 우선" 같은 암묵적 규칙에 의존하지 않는다).
- 의사결정표는 §4 함수 계약의 사전조건(입력 조건)·사후조건(기대 동작)과 반드시 일치해야 한다.

## 3. 상태 의존 로직과의 관계

의사결정표의 조건이나 알고리즘의 분기가 상태(§8 상태전이 상세)에 의존하면, 상태 이름과 전이 조건이
상태전이 절의 정의와 정확히 일치하는 용어를 사용한다.
