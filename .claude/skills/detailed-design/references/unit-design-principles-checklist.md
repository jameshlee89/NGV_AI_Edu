# 단위 설계 원칙 체크리스트 (응집도 · 결합도 · ISO 26262 단위 설계 원칙)

SKILL.md §3(모듈 분해)과 §7(코딩 및 검증 규칙), §12(최종 자체 검토)에서 사용한다. 상세설계 단계에서도
`architecture-design` 스킬의 응집도/결합도/SOLID 원칙이 모듈·함수 수준까지 그대로 이어진다.

## 1. 응집도 (단위 수준)

- [ ] 하나의 모듈/함수가 하나의 명확한 책임만 수행하는가?
- [ ] 함수 이름과 실제 동작이 정확히 일치하는가? ("그리고"로 여러 동작을 설명해야 한다면 분리를
      검토한다)
- [ ] 서로 관련 없는 자료형/상수가 같은 공통 자료형 모듈에 섞여 있지 않은가? (§4 공통 자료형)

## 2. 결합도 (단위 수준)

- [ ] 함수/모듈 간 호출이 아키텍처 설계서에서 정의한 인터페이스 경계를 넘지 않는가?
- [ ] 전역 변수/공유 가변 상태에 대한 암묵적 의존이 없는가? 있다면 접근 규칙(동기화, 소유권)이
      명시되어 있는가?
- [ ] 함수가 필요한 데이터만 매개변수로 받는가? (숨은 의존, 과도한 컨텍스트 객체 전달 지양)
- [ ] 상세 호출관계(§3)에 순환 호출이 없는가? 있다면 아키텍처 설계서의 순환 의존 금지 원칙과 충돌하지
      않는지 확인한다.

## 3. 복잡도 제한

- [ ] 함수 하나의 분기/순환 복잡도가 과도하지 않은가(프로젝트 코딩 표준에 기준치가 있으면 그것을
      따르고, 없으면 "복잡도 기준 확인 필요"로 표시)?
- [ ] 하나의 함수가 여러 단계의 중첩 조건/반복문으로 읽기 어렵게 되어 있지 않은가? (필요 시 보조
      함수로 분리)

## 4. ISO 26262 Part 6 단위 설계·구현 원칙과의 연결 (요약 — 원문 대조 필요)

ISO 26262 Part 6은 소프트웨어 단위 설계 및 구현에서 다음과 같은 성격의 원칙을 요구한다(정확한 절/표
번호와 문구는 이 요약만으로 단정하지 말고 `references/iso26262-aspice-detailed-design-checklist.md`의
안내에 따라 공식 표준 문서로 확인한다):

- 하나의 진입점·하나의 종료점을 갖는 구조화된 제어 흐름(불필요한 무조건 분기/goto류 회피)
- 포인터 사용 제한 및 안전한 사용 규칙
- 동적 메모리 할당/동적 객체 생성의 제한적 사용(사용한다면 근거와 실패 처리 명시)
- 재귀 사용의 제한(사용한다면 종료 조건과 최대 깊이 명시)
- 인터럽트 사용의 제한과 우선순위/재진입 안전성 고려
- 암묵적 형변환 회피, 강한 타입 사용
- 도달 불가능한 코드(dead code)·미사용 코드 금지
- 명확하고 모호하지 않은 표기법 사용, 언어 서브셋/코딩 표준 준수(예: 프로젝트가 MISRA류 표준을
  지정했다면 그 표준을 우선 적용)

## 5. 방어적 프로그래밍과의 연결

위 원칙 중 오류 검출·방어 동작과 관련된 부분은 `references/error-handling-defensive-guide.md`에서
더 구체적으로 다룬다.

## 6. 프로젝트 코딩 표준 우선순위

1. 프로젝트에 지정된 코딩 표준 문서가 있으면(예: `docs/`, 사용자가 알려준 경로) 그것을 최우선으로
   따른다.
2. 없으면 이 체크리스트를 잠정 기준으로 사용하되, 산출물에 "사내/프로젝트 코딩 표준 확인 필요"를
   명시한다.
