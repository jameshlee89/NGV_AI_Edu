때는 항상 아래 원본을 복사해서 사용한다.

## TPL-SWE2-001 장 구성 (실제 원본에서 추출)

표지: 템플릿 ID(`TPL-SWE2-001`), 적용 프로세스(`SWE.2`), 프로젝트, 작성 문서 ID/명칭, 버전 및
베이스라인, 작성자/검토자.

문서 통제: 변경 이력(Revision/변경일/작성 역할/변경 내용/검토 상태), 작성·검토·승인 상태(구분/역할
또는 성명/상태/일자/증거 위치).

목차 이하 본문 15개 장:

1. 목적 및 적용범위
   1.1 목적 — 문서가 지원하는 개발/검증 활동과 기대 결과
   1.2 적용범위 — 적용 제품, SW 구성요소, 생명주기 단계, 대상 조직
   1.3 적용 경계 — 포함/제외 범위, 외부 조직·상위 산출물과의 경계
2. 아키텍처 설계 원칙 — 분해, 결합도, 응집도, 인터페이스, 오류 격리, 변경 용이성에 적용한 원칙
3. 논리 아키텍처
   3.1 아키텍처 요소 — 각 요소의 ID, 명칭, 목적, 제공 기능, 소유 책임
   3.2 관계와 제약 — 허용된 의존 방향, 호출 관계, 공유 자원, 금지된 결합
4. 컴포넌트 책임 — 컴포넌트별 책임, 입력, 출력, 상태, 오류 처리, 할당 요구사항
5. 정적 의존성 — 패키지/모듈/컴포넌트 정적 의존성, 순환 의존 방지 기준
6. 인터페이스 명세 — 인터페이스 ID, 제공자, 사용자, 데이터, 호출 조건, 시간 제약, 오류 계약
   6.1 내부 인터페이스 — SW 요소 간 API, 이벤트, 데이터 저장소, 동기화 규칙
   6.2 외부 인터페이스 — 하드웨어/통신/사용자/외부 서비스와의 경계와 변환 책임
7. 동적 동작 — 주요 시나리오의 호출 순서, 데이터 흐름, 조건별 분기(시퀀스/활동 관점)
8. 상태 전이 — 상태, 진입/종료 조건, 전이 이벤트, 가드, 금지 전이
9. 오류 격리와 안전 동작 — 오류 감지 위치, 전파 차단, 안전 상태, 복구와 진단 정보 책임
10. 품질속성 분석 — 성능, 신뢰성, 유지보수성 등 주요 품질속성 시나리오와 설계 대응
11. 통합 전략 — 통합 단위, 순서, 인터페이스 검증, 스텁/드라이버, 회귀 범위
12. 요구사항 할당 — SW 요구사항을 아키텍처 요소/인터페이스에 할당, 누락/중복 확인
13. 자원 및 배포 경계 — 실행 노드, 프로세스, 메모리, CPU, 저장소, 배포 제약
14. 추적성 — 요구사항, 아키텍처 요소, 상세설계, 통합 검증 간 연결
15. 참고자료 — 입력 요구사항, 적용 표준, 모델 원본, 설계 결정 기록

## 적용 방법

- 새 산출물 작성 시 위 두 파일을 복사한 뒤 `WP_Templates/Engineering/README.md` 규칙대로
  `<산출물 ID>_<산출물명>.<확장자>` 형식으로 파일명을 바꾸고 실제 프로젝트 정보를 채운다.
- SKILL.md의 §1 표는 위 15개 장 구성을 그대로 옮긴 것이므로, 실제 작성 시에는 이 파일이 아니라
  SKILL.md §1을 목차 기준으로 사용한다. 이 파일은 원본 템플릿 내용이 바뀌었는지 대조하는 참고용이다.
- 만약 템플릿 원본이 갱신되거나 다른 경로로 교체되면, 이 파일과 SKILL.md §1을 함께 갱신한다.
