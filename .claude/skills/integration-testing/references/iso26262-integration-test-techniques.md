# ISO 26262 Part 6 근거 통합시험 기법 (요약 — 원문 대조 필요)

> ⚠️ 아래는 통합시험 설계 시 반영해야 할 항목을 정리한 **요약**이다. 실제 감사/인증 대응 문서에 표
> 번호나 원문, ASIL별 권고 수준(++/+/o)을 인용해야 한다면, 이 요약만으로 단정하지 말고 프로젝트에
> 첨부된 공식 ISO 26262 Part 6 문서로 정확한 번호와 문구를 확인한다.

## 1. 시험 방법 (무엇을 확인하는가)

ISO 26262 Part 6은 소프트웨어 통합시험을 위한 방법으로 다음과 같은 성격의 기법을 다룬다(정확한 표
번호와 ASIL별 권고 수준은 공식 문서로 확인):

| 기법 | 목적 | 이 스킬에서의 적용 지점 |
|---|---|---|
| 요구사항기반시험 (Requirements-based test) | 아키텍처/SW 요구사항으로부터 시험 케이스를 직접
  도출 | SKILL.md §6, TPL-SWE5-002의 `Trace` 컬럼 |
| 인터페이스시험 (Interface test) | 컴포넌트 간·외부 인터페이스가 계약(입출력, 오류 계약, 시간
  제약)대로 동작하는지 확인 | SKILL.md §2, §4 — 아키텍처 인터페이스가 시험 베이시스 |
| 결함주입시험 (Fault injection test) | 오류를 의도적으로 주입해 오류 검출·격리·안전 상태 전이가
  설계대로 동작하는지 확인 | 아키텍처 설계서의 오류 격리 설계(§7~9장)가 있는 인터페이스에 적용 |
| 자원사용시험 (Resource usage test) | 메모리, CPU, 통신 대역 등 자원 사용이 설계 범위 내인지 확인 |
  아키텍처 설계서 품질속성 분석(10장)/자원 및 배포 경계(13장)와 연계 |
| 백투백비교시험 (Back-to-back comparison test) | 모델과 생성된 코드의 동작을 비교(모델 기반 개발을
  사용하는 경우) | 해당 프로젝트가 모델 기반 개발을 사용하는 경우에만 적용 |

## 2. 시험 케이스 도출 기법 (어떻게 케이스를 만드는가)

기법의 일반적 정의(동등분할, 경계값분석, 오류추정 등)는 `.claude/skills/sw-system-test/references/
test-design-techniques.md`를 단일 기준으로 삼는다 — 이 문서에서 다시 정의하지 않는다. 통합시험
맥락에서 각 기법을 어떻게 적용하는지만 정리한다.

| 기법 | 통합시험에서의 적용 |
|---|---|
| 동등분할 | 아키텍처 인터페이스(`IF-XXX`)의 입력 도메인을 유효/무효 클래스로 나눠 검증 |
| 경계값분석 | 상세설계 함수 계약(`detailed-design` 스킬)의 경계값을 인터페이스 호출 시점에서 검증 |
| 오류추정 | 결함주입시험(§1)과 결합해, 인터페이스 오류 계약이 실제로 지켜지는지 검증 |

## 3. 함수 커버리지 · Call 커버리지와의 관계

ISO 26262 Part 6은 소프트웨어 아키텍처 수준의 구조적 커버리지 지표로 **함수 커버리지**와 **Call
커버리지**(또는 이에 준하는 인터페이스 호출 커버리지) 성격의 지표를 다룬다. 이 프로젝트는 ASIL별
권고 수준과 무관하게 **사용자 지시에 따라 두 지표 모두 100% 달성을 목표로 한다**(SKILL.md §5,
`references/coverage-measurement-guide.md` 참고). 정확한 표 번호·용어·ASIL별 권고 수준은 이 요약만으로
단정하지 말고 공식 표준 문서로 확인한다.
