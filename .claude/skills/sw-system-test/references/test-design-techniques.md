# 테스트 설계 기법 카탈로그 (ISO 29119/ISTQB 기반)

이 파일은 이 저장소 전체에서 **경계값분석·동등분할·오류추정 등 고전적 블랙박스 테스트 설계 기법의
정의를 통일하는 단일 기준**이다. `tdd`, `integration-testing` 스킬은 이 기법들을 각자 다시 정의하지
않고 이 파일을 참조하며, 자신의 시험 수준(단위/통합)에서 그 기법을 어떻게 적용하는지만 별도로 설명한다.

## 1. 경계값 분석 (Boundary Value Analysis)

검증기준에 수치·범위·임계값이 있는 경우, 경계값 미만/경계값/경계값 초과를 각각 별도 케이스로
도출한다.

- 예: "온도는 -20°C ~ 80°C 범위에서 정상 동작해야 한다" → -21°C(경계 미만), -20°C(하한 경계),
  80°C(상한 경계), 81°C(경계 초과) 4개 케이스.

## 2. 동치 클래스 / 동등분할 (Equivalence Partitioning)

입력 도메인을 유효/무효 클래스로 나누고, 각 클래스를 대표하는 값 하나로 검증한다(클래스 내 모든 값이
동일하게 처리된다고 가정).

- 예: 입력이 "1~100 사이의 정수"라면 유효 클래스(예: 50), 무효 클래스 두 개(0 이하, 101 이상)로
  나눠 각각 대표값을 선택한다.

## 3. 조합 테스트 (전 조건 조합, Full Combinatorial Testing)

관련 조건 수가 적어 모든 조합을 실행하는 것이 현실적일 때, 조건들의 전체 조합을 빠짐없이 검증한다.

## 4. 페어와이즈 (Pairwise Testing)

조건·값의 조합 수가 많아 전수 조합이 비현실적인 경우, 모든 "두 조건의 쌍"이 최소 한 번은 나타나도록
하는 축소된 조합 집합으로 대체한다. 오픈소스 도구 **PICT**로 생성한다.

## 5. 엣지 케이스 (Edge Case)

정상 범위의 극단, 동시성/타이밍, 자원 고갈 등 일반적인 동치분할/경계값분석으로는 포착되지 않는 특이
조건을 다룬다.

## 6. 경험 기반 테스트 (Experience-based Testing)

유사 시스템의 결함 이력이나 QA 경험에 근거해 오류를 추정한다(오류 추정, 탐색적 테스트 등). 정형화된
분석 기법으로 놓치기 쉬운 실무 결함 패턴을 보완한다.

## 7. 다른 시험 수준에서의 적용 (교차 참조)

같은 기법이라도 시험 수준에 따라 목적과 근거가 다르다.

| 기법 | 시스템 시험(`sw-system-test`, 이 파일) | 통합 시험(`integration-testing`) | 단위 시험(`tdd`) |
|---|---|---|---|
| 경계값분석 | SW 요구사항 명세서의 수치 기준 | 아키텍처 인터페이스/상세설계 함수 계약의 경계값 | 함수 계약의 사전조건 경계값 |
| 동등분할 | SW 요구사항의 입력 도메인 | 인터페이스 입력 도메인 | 함수 매개변수의 유효/무효 클래스 |
| 오류추정 | 유사 시스템/제품 결함 이력 | 인터페이스 오류 계약, 결함주입시험과 결합 | 방어적 코드(오류 처리) 검증 |

`integration-testing`은 여기에 결함주입시험·자원사용시험 등 구조적 시험 방법을, `tdd`는 상태전이
테스트·결정테이블 테스트·버그 재현(회귀) 등 단위 코드 검증에 특화된 기법을 추가로 정의한다 — 각 스킬의
`references/` 폴더 참고.
