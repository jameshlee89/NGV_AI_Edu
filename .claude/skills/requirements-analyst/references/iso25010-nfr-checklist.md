# ISO/IEC 25010 품질특성 기반 비기능 요구사항 체크리스트

모든 비기능 요구사항(NFR)은 아래 8대 품질특성 중 하나 이상에 명시적으로 매핑되어야 한다. 하위특성은
대표적인 것만 나열했으며, 정확한 세부 정의가 필요하면 표준 원문을 확인한다.

| 품질특성 | 대표 하위특성 | 전형적 NFR 예시(작성용, 실제 값은 프로젝트에 맞게) |
|---|---|---|
| 1. 기능적합성 | 완전성, 정확성, 적절성 | 시스템은 정의된 모든 입력 조합에 대해 규격서 §X의 계산 결과와 오차 0.1% 이내로 일치해야 한다 |
| 2. 성능효율성 | 시간반응성, 자원활용성, 용량 | 동시 사용자 N명 조건에서 API 응답시간 P95 ≤ Xms여야 한다 |
| 3. 호환성 | 공존성, 상호운용성 | 시스템은 기존 X 시스템과 동일 네트워크에서 리소스 충돌 없이 동작해야 한다 |
| 4. 사용성 | 인식적합성, 학습성, 운용성, 오류방지, UI심미성, 접근성 | 신규 사용자가 교육 없이 핵심 작업 X를 Y분 이내에 완료할 수 있어야 한다 |
| 5. 신뢰성 | 성숙성, 가용성, 결함허용성, 회복성 | 시스템 가용성은 월간 99.X% 이상이어야 하며, 장애 발생 시 Y초 이내 자동 복구되어야 한다 |
| 6. 보안성 | 기밀성, 무결성, 부인방지, 책임추적성, 인증성 | 모든 사용자 인증 실패 시도는 로그로 기록되어 재구성 가능해야 한다 |
| 7. 유지보수성 | 모듈성, 재사용성, 분석용이성, 수정용이성, 시험용이성 | 모듈 X의 순환복잡도는 Y 이하로 유지되어야 한다 |
| 8. 이식성 | 적응성, 설치성, 대체성 | 시스템은 OS X/Y 환경에서 코드 변경 없이 빌드/실행되어야 한다 |

## 검증방안 작성 규칙 (실행 가능성 필수)

검증방안을 쓰기 전에 다음을 스스로 점검하고, 하나라도 "아니오"면 검증방안을 확정하지 말고
"실행 가능 여부 확인 필요"로 표시한다.

1. 이 검증을 수행할 도구/환경이 실제로 존재하거나 확보 가능한가? (없는 도구를 전제로 하지 않는다)
2. 측정 기준값이 숫자/이분법적 판정으로 표현되어 있는가? ("충분히", "적절히" 금지)
3. 이 프로젝트의 개발 단계·자원으로 실제 수행 가능한 절차인가? (이론적으로만 가능한 방법 금지)
4. 검증 결과를 누가, 언제, 어떤 산출물로 남기는지 명시했는가?

## 나쁜 예 → 좋은 예

- 나쁜 예: "시스템은 안전해야 한다" / 검증: "보안 검토를 한다"
- 좋은 예: "시스템은 OWASP Top 10 항목에 대해 알려진 취약점이 0건이어야 한다" /
  검증: "OWASP ZAP으로 자동 스캔을 수행하고 결과 리포트의 High/Critical 항목 수가 0인지 확인한다"

- 나쁜 예: "UI는 사용하기 편해야 한다" / 검증: "사용자가 만족하는지 설문한다"
- 좋은 예: "신규 사용자 10명 중 8명 이상이 사전 교육 없이 핵심 작업을 5분 이내 완료해야 한다" /
  검증: "사용성 테스트 세션을 진행하고 완료 시간과 성공 여부를 기록한다"
