# EARS 문형 가이드 (명확성 확보)

EARS(Easy Approach to Requirements Syntax)는 요구사항을 애매함 없이, 검증 가능한 하나의 문장으로
쓰기 위한 표준화된 문형 모음이다. 요구사항 하나마다 아래 6가지 패턴 중 가장 적합한 것을 고른다.

## 1. 유비쿼터스 (항상 참인 요구사항)
```
THE <시스템> SHALL <응답>
```
예: THE 시스템 SHALL 모든 사용자 입력을 UTF-8로 처리한다.

## 2. 이벤트 기반 (특정 트리거 발생 시)
```
WHEN <트리거 이벤트>, THE <시스템> SHALL <응답>
```
예: WHEN 사용자가 로그인 버튼을 클릭하면, THE 시스템 SHALL 자격증명을 검증한다.

## 3. 상태 기반 (특정 상태 동안 지속)
```
WHILE <상태>, THE <시스템> SHALL <응답>
```
예: WHILE 차량이 주행 중인 상태일 때, THE 시스템 SHALL 운전자 경고 화면 조작을 비활성화한다.

## 4. 원치 않는 동작 (예외/오류 처리)
```
IF <원치 않는 조건>, THEN THE <시스템> SHALL <응답>
```
예: IF 센서 신호가 유효 범위를 벗어나면, THEN THE 시스템 SHALL 안전 상태로 전환하고 경고를 기록한다.

## 5. 선택 기능 (옵션 사양에만 적용)
```
WHERE <기능/옵션이 포함된 경우>, THE <시스템> SHALL <응답>
```
예: WHERE 고급 진단 옵션이 활성화된 경우, THE 시스템 SHALL 상세 오류 코드를 로그에 기록한다.

## 6. 복합 (여러 조건 결합 — 단, 원자성은 유지)
```
WHILE <상태>, WHEN <트리거>, THE <시스템> SHALL <응답>
```
예: WHILE 시스템이 초기화 상태일 때, WHEN 자가진단이 실패하면, THE 시스템 SHALL 기동을 중단하고
오류 코드를 표시한다.

## 작성 시 체크리스트

- [ ] 문장에 "그리고"/"또는"으로 묶인 서로 다른 요구가 없는가 (있다면 별도 ID로 분리)
- [ ] 애매한 형용사(빠르게/적절히/충분히/안전하게 등)가 측정 가능한 기준으로 구체화되었는가
- [ ] 주어(시스템/컴포넌트명)가 명시적인가 ("그것은", "적절한 처리를 한다" 같은 대명사/모호한 서술 금지)
- [ ] SHALL(의무), SHOULD(권고), MAY(선택)를 우선순위에 맞게 구분해서 썼는가
- [ ] 이 요구사항만 보고 검증 담당자가 통과/실패를 판정할 수 있는가
