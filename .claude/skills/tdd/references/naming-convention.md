# 네이밍 규칙 (함수명 · 변수명)

SKILL.md §3에서 사용한다. CLAUDE.md 구현 지침의 "함수명, 변수명은 3글자 이상 사용하고, 낙타 표기법을
활용한다"를 구체화한다.

## 1. 규칙

- **최소 길이 3글자**: 함수명과 변수명은 축약 없이 최소 3글자 이상이어야 한다. 반복문 인덱스, 임시
  변수도 예외 없다.
- **낙타 표기법(camelCase)**: 함수/변수 모두 첫 단어는 소문자로 시작하고, 이어지는 단어의 첫 글자를
  대문자로 쓴다. Python 표준 관례인 `snake_case`는 이 프로젝트에서 사용하지 않는다(프로젝트 지정
  규칙이 PEP8보다 우선한다).
- 이름은 축약어보다 온전한 단어를 사용해 의미가 분명하게 한다(3글자 이상 규칙과도 자연히 맞는다).

## 2. 좋은 예 / 나쁜 예

| 나쁜 예 | 문제 | 좋은 예 |
|---|---|---|
| `i` | 3글자 미만 | `idx` (허용 최소 예시) 또는 `rowIndex` |
| `x`, `y` | 3글자 미만, 의미 불명확 | `posX`, `posY` |
| `calc_total` | snake_case | `calcTotal` 또는 `calculateTotal` |
| `tmp` | 의미 불명확(3글자는 충족) | `tempBuffer` |
| `retry_count` | snake_case | `retryCount` |
| `getValue2` | 의미 불명확한 접미사 숫자 | `getSecondaryValue` |

## 3. 적용 범위와 예외

- 이 규칙은 함수명과 변수명(매개변수 포함)에 적용한다.
- 클래스명, 모듈 레벨 상수 등 CLAUDE.md가 별도로 언급하지 않는 대상은 언어 관례(클래스는
  `PascalCase`, 상수는 `UPPER_SNAKE_CASE`)를 유지한다. 다만 프로젝트가 이후 별도 지정을 하면 그것을
  우선한다.
- 표준 라이브러리/외부 라이브러리가 요구하는 콜백 시그니처(예: `__init__`, `__str__` 같은 매직
  메서드)는 언어 규약을 따른다 — 이 규칙 위반으로 보지 않는다.

## 4. 자동 점검

`references/quality-metrics-tools.md` §5의 `pylint` 정규식 설정으로 자동 점검한다. 설정이 어려우면
구현 직후 직접 목록을 검토한다.

## 5. 예외 — 테스트 메서드명

`unittest`는 테스트 메서드명이 `test`로 시작해야 자동으로 검색·실행한다. 이 접두사는 예외로 허용하고,
그 뒤는 camelCase로 잇는다(예: `testReturnsDistanceForTwoPoints`). 전체 길이가 3글자 이상이라는
조건은 `test` 접두사만으로 이미 충족되므로 별도 확인이 필요 없다. 테스트 문서화 규칙(Doxygen
목적 설명·기법·긍정/부정 케이스)은 `references/test-documentation-guide.md`를 따른다.
