# 품질 지표 측정 오픈소스 도구 가이드

SKILL.md §2에서 사용한다. CLAUDE.md가 요구하는 4가지 품질 지표를 실제로 측정하기 위한 오픈소스 도구
사용법이다. **도구가 설치되어 있는지 먼저 확인**하고, 없으면 설치를 사용자에게 안내한다 — 실행하지
않고 지표를 추정하지 않는다.

## 0. 사전 확인

```
python --version        # 또는 python3 --version — Python 3.14 계열인지 확인
python -m pip show radon flake8 pylint 2>&1   # 설치 여부 확인 (없으면 오류 출력됨)
```

`cloc`은 Python 패키지가 아니라 별도 배포 도구이므로 `cloc --version`으로 확인한다.

## 1. 함수 순수 코드 라인수 (기준: 50줄 이하)

`radon raw` 또는 `radon cc`로 함수 단위 정보를 얻는다.

```
python -m pip install radon   # 설치 필요 시
radon raw <파일 또는 디렉터리>          # LOC, LLOC(논리적 코드 라인), 주석 라인 등 출력
radon cc <파일 또는 디렉터리> -s -a     # 함수별 복잡도와 함께 각 블록 정보 표시
```

- "순수 코드 라인"은 주석·빈 줄을 제외한 실제 코드 라인(LLOC에 가깝다)으로 계산한다. `radon raw`의
  `LLOC` 값을 함수 단위로 확인하려면 함수별로 파일을 쪼개서 실행하거나, 함수 시작/끝 라인을 확인한 뒤
  해당 범위만 잘라 측정한다.
- 50줄을 넘는 함수는 책임을 분리해 리팩터링한다(§7 SOLID/응집도 원칙과 동일한 접근).

## 2. 함수 순환복잡도 (기준: 10 이하)

```
radon cc <파일 또는 디렉터리> -s        # 함수별 복잡도와 등급(A~F) 표시
# 또는
python -m pip install flake8            # 설치 필요 시
flake8 --max-complexity=10 <파일 또는 디렉터리>   # mccabe 플러그인 내장, 10 초과 시 경고
```

- `radon cc`의 등급 기준: A(1-5), B(6-10), C(11-20)... 이 프로젝트 기준(10 이하)은 A~B 등급까지만
  허용한다는 뜻이다.
- 복잡도가 높은 함수는 조건 분기를 보조 함수로 추출하거나, 정책 의사결정표(상세설계서)를 데이터
  기반 처리로 바꿔 복잡도를 낮춘다.

## 3. 중복 코드 (기준: 7줄까지 허용)

```
python -m pip install pylint            # 설치 필요 시
pylint --disable=all --enable=duplicate-code --min-similarity-lines=8 <디렉터리>
```

- `min-similarity-lines`를 8로 설정하면 8줄 이상 중복만 보고되므로, "7줄까지 허용"과 맞아떨어진다
  (7줄 이하 중복은 보고되지 않고 허용, 8줄 이상부터 위반으로 간주).
- 대안: `jscpd`(Node.js 기반, 여러 언어 지원)를 사용할 수도 있다 —
  `npx jscpd --min-lines 8 <디렉터리>`. 프로젝트에 Node.js 환경이 없다면 `pylint`를 우선한다.
- 중복이 발견되면 공통 로직을 함수/모듈로 추출해 제거한다.

## 4. 주석 비율 — Doxygen 방식, 20% 이상

```
cloc <디렉터리>
```

- `cloc` 출력의 `Python` 행에서 `blank`, `comment`, `code` 라인 수를 확인한다.
- 주석 비율 = `comment / (comment + code)` (또는 프로젝트가 별도 계산식을 지정하면 그것을 따른다)로
  계산하고 20% 이상인지 확인한다.
- 비율이 낮으면 의미 없는 주석을 채우지 말고, 아직 Doxygen 주석이 없는 함수/클래스에
  `references/doxygen-comment-guide.md` 형식으로 실제 설명(계약, 설계 의도)을 추가한다.

## 5. 네이밍 규칙 (3글자 이상, camelCase)

```
python -m pip install pylint            # 설치 필요 시
```

`.pylintrc` 또는 `pyproject.toml`의 `[tool.pylint.basic]`에 다음과 같이 정규식을 지정하면 자동
점검이 가능하다(프로젝트에 이미 다른 설정이 있으면 병합한다).

```ini
[BASIC]
function-rgx=[a-z][a-zA-Z0-9]{2,}$
variable-rgx=[a-z][a-zA-Z0-9]{2,}$
argument-rgx=[a-z][a-zA-Z0-9]{2,}$
```

- 위 정규식은 "소문자로 시작 + 전체 3글자 이상 + 영숫자만"을 강제한다(camelCase 첫 글자 소문자 규칙과
  일치).
- 정적 도구 설정이 어려운 경우, 구현 직후 사람이 직접 목록을 훑어보며 점검해도 되지만, 가능하면 위
  설정으로 자동화한다.

## 6. 도구 미설치 시 처리

- 설치 명령을 사용자에게 제시하고, 사용자가 설치를 승인/수행하기 전까지는 "지표 확인 필요(도구 미설치)"
  로 명시한다.
- 오프라인 환경 등으로 설치가 불가능하면, 수동 점검 방법(예: 함수 라인 수를 직접 세기, 조건문 개수로
  복잡도 어림)을 보조 수단으로 쓰되 이는 근사치이며 도구 측정을 대체하지 않는다는 점을 보고서에
  명시한다.
